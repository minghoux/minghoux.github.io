The core design system foundation for Abound. A cohesive set of tokens, components, and patterns to build premium financial experiences.

Design Principles

Four principles that guide every design and engineering decision at Abound. This system bridges the agency's brand identity with day-to-day product implementation.

1

Clarity over decoration

Clean UI that builds trust in a lending product. Every element earns its place. If it doesn't aid comprehension or action, remove it.

2

Accessible by default

WCAG 2.1 AA minimum. Accessibility is built into tokens and components — not bolted on after the fact.

3

Progressive disclosure

Reduce cognitive load. Reveal complexity step by step. A loan application should feel guided, never overwhelming.

4

Brand-consistent, not brand-heavy

Forest Green is the accent, not the wallpaper. Follow the 60/30/10 rule: 60% neutral, 30% brand, 10% semantic colour.

Accessibility Checklist

WCAG 2.1 AA compliance is the baseline, not the goal. These rules are non-negotiable.

Colour Contrast

Minimum 4.5:1 for body text. 3:1 for large text (18px+) and UI components. All primary pairings verified in the accessibility matrix above.

Focus Indicators

2px solid Forest Green with 2px offset on all interactive elements. Visible in all states. Never remove :focus-visible.

Touch Targets

Minimum 44×44px for all interactive elements. Buttons, links, checkboxes, and radio buttons all meet this threshold.

Screen Reader

All form inputs labelled. Error messages announced via aria-live. Progress steps convey position. Decorative images marked aria-hidden.

Colour Independence

Never use colour alone to convey status. Always pair with icon + text. See badges for reference — every variant includes a shape indicator.

Financial Figures

Tabular numerals (tabular-nums), right-aligned, clear currency symbols (£). Screen readers announce currency values naturally.

Design Rationale & Recommendations

What was kept from the agency brand, what was added for product UI, and what should be refined.

What I kept from the agency brand

  • Forest Green (#0E4533) as the hero brand colour — excellent contrast (10.2:1 on white), distinctive, trust-signalling for a lending product.
  • Charcoal (#201F1D) for primary text — near-black but warmer than pure #000, reducing harshness on long-form reading.
  • The soft, natural illustration textures — perfect for marketing pages. The organic feel differentiates Abound from cold, corporate fintech competitors.
  • Teal/Sage, Khaki, Lime — retained as accent/marketing colours. They give Abound a distinctive, nature-inspired personality.

What I added (and why)

  • Extended neutral scale (Neutral 50–900) — the agency palette had no mid-greys, which are essential for UI hierarchy: borders, backgrounds, secondary text, disabled states.
  • Feedback colours (Success, Danger, Warning, Info) — red/amber/green/blue semantic colours are non-negotiable for a lending product that needs to communicate approvals, errors, warnings, and status.
  • Specific border, shadow, and spacing tokens — the agency defined brand identity, not product implementation details. These tokens ensure consistency across Webflow and React.
  • DM Sans as Saans fallback — closest geometric match available on Google Fonts. When Saans files arrive, it's a one-line swap.
  • Interactive colour states — hover (#0A3325) and pressed (#071F17) variants of Forest Green, plus disabled states using the neutral scale.

What I recommend changing or refining

  • Off-White (#F4F8F3) vs Pale Yellow-Green (#F7F7E9) — these are nearly indistinguishable (approximately 1.01:1 contrast ratio). Recommend using Off-White as the primary surface and reserving Pale Yellow-Green only for marketing hero sections. For UI layering, use the Neutral scale instead.
  • Teal/Sage (#B8DCD2) in product UI — works beautifully for marketing backgrounds but could be confused with a success/positive state in the product. Reserve for decorative and marketing use only.
  • Khaki (#EDEABE) and Lime (#D4F19B) — strong accents but should be used sparingly: callout boxes, marketing highlights, not core UI surfaces. Overuse risks looking unfinished or playful, which undermines trust in a lending product.
  • Future consideration: dark mode — the current system is light-mode only. If dark mode is needed, the semantic token architecture supports it with minimal effort — swap the primitive values mapped to each token.
